# T-006 — Implement parallel task coordination and integration checks

- **Task ID:** T-006
- **Title:** Implement parallel task coordination and integration checks
- **Status:** BLOCKED
- **Owner role:** backend
- **Terminal:** TEAM-BE
- **Primary provider:** Codex
- **Fallback provider:** Antigravity
- **Capability profile:** standard
- **Parallelism:** SEQUENTIAL / BLOCKED

## Objective

Allow manually dispatched Codex and Antigravity specialists to execute independent FE/BE tasks concurrently with shared contracts, isolated workspaces and visible coordination checks.

## Requirements

- Follow T-001 contracts; implement in scripts/zankai/coordination/** with a canonical project coordination store shared across worktrees rather than independent per-worktree claims.
- Atomically claim a task for one named session and reserve declared scopes. Reject duplicate claims and unresolved overlapping ownership. Stale claims require explicit recovery, not automatic reassignment.
- Check dependencies, contract revision and base commit before recommending dispatch. Enable paired FE/BE readiness after their shared contract integrates; do not serialize independent work unnecessarily.
- Offer explicitly invoked Git worktree preparation using argument arrays, validated workspace paths and separate branches. Report Git/base commit absence clearly. Do not initialize Git, commit, launch providers, merge or remove worktrees automatically.
- Assign dev ports and record isolated test resource identifiers; report collisions without provisioning or modifying databases.
- Generate worker context with task, workspace, allowed paths, restricted paths and contract revision. Support structured change requests for shared files/contracts.
- Inspect changed tracked/untracked paths for scope violations and shared-file overlaps before integration. Label reservations as advisory unless a verified execution permission mechanism enforces them.
- Record a human-controlled integration queue with ready/blocked/needs-review outcomes. Never interpret conflict-free diffs or successful exits as integrated QA approval.
- Expose stable APIs to the T-004 dashboard; preserve board single-writer rules and legacy scripts.

## Acceptance criteria

- [ ] Two concurrent claims for one task cannot both succeed.
- [ ] Independent FE/BE tasks with the same accepted contract can be recommended together; overlapping tasks are flagged.
- [ ] Missing Git, invalid workspace, stale claims, contract mismatch, resource collisions and out-of-scope changes are tested.
- [ ] Worktree fixtures show agents cannot overwrite each other's working files; semantic compatibility still requires QA.
- [ ] No provider spawning, automatic merging, board edits or destructive cleanup occurs.
