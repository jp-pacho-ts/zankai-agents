## Objective

Prepare a locally tested npm CLI artifact for later GitHub hosting and registry release; no upload or publication in this task.

## Requirements

- Follow T-001 distribution contracts; add `bin` mapping for `zankai`, Node shebang, explicit files allowlist and Node >=20 support.
- Package clean templates, role adapters, routing defaults and required CLI assets without live project tasks/handoffs/runtime, secrets or local provider credentials. Inspect actual tarball contents.
- Resolve bundled assets relative to package location and writes relative to the consumer project. Preserve existing project documents, dependencies and scripts.
- Keep existing zankai:* commands usable. Optional consumer aliases must invoke installed CLI, not missing copied files.
- No install/postinstall initialization, interactive prompts or provider launch. Users explicitly run `zankai init`.
- Verify desired package name `zankai` availability/ownership before final public metadata; propose a scoped name if unavailable. Never install an unrelated package for this check.
- Document local tarball, GitHub source and npm registry installation separately. GitHub URL, license and publisher identity require Team Lead input; do not invent them.
- Retain private:true until authorized release. No GitHub upload, npm publish, automatic commit or merge.

## Acceptance criteria

- [ ] Local tarball installs in a temporary consumer project and its CLI runs outside the source repo, including Windows bin shims.
- [ ] `zankai init`, `zankai status`, `zankai --help` and local `npx --no-install zankai --help` work per contracts.
- [ ] Artifact inventory excludes secrets and live project/runtime data; initialization does not write to installation directories.
- [ ] Existing consumer files/scripts are preserved and installation has no interactive side effects.
